# VoxNote

Спецификация локального приложения для транскрибации русскоязычных аудиозаписей.

**Статус:** планирование MVP  
**Целевая платформа:** Windows 10/11 x64  
**Модель распространения:** открытый исходный код и готовые сборки через GitHub  
**Основной принцип:** аудио обрабатывается локально и не покидает компьютер пользователя  
**Последнее обновление спецификации:** 19 ноября 2026 года

## 1. Назначение

VoxNote — настольное приложение, которое преобразует русскую речь из аудиофайла в обычный текст. Пользователь выбирает файл, наблюдает за ходом локальной транскрибации, получает готовый текст и может скопировать его либо сохранить в формате `.txt`.

Приложение ориентировано на лекции, заметки, интервью и другие продолжительные записи. Для специализированной речи предусмотрены тематические словари, помогающие модели распознавать редкие термины.

## 2. Возможности MVP

- выбор файла через системное окно;
- перетаскивание файла в окно приложения;
- поддержка `.m4a`, `.mp3`, `.wav`, `.flac` и `.ogg`;
- распознавание русской речи;
- полностью локальная обработка;
- использование NVIDIA GPU при наличии совместимого оборудования;
- автоматический переход на CPU, если GPU недоступен;
- выбор одной из трёх моделей с понятным описанием скорости и качества;
- загрузка выбранной модели при первом запуске или позднее через настройки;
- хранение нескольких загруженных моделей с возможностью переключения;
- отображение прогресса, прошедшего и приблизительно оставшегося времени;
- возможность отменить обработку;
- просмотр и локальное редактирование результата с автосохранением и историей версий;
- копирование результата в буфер обмена;
- сохранение результата в UTF-8 `.txt`;
- светлая, тёмная и системная темы;
- выбор терминологического словаря перед запуском транскрибации.

## 3. Что не входит в MVP

- распознавание видеофайлов;
- разделение текста по говорящим;
- таймкоды и экспорт субтитров;
- облачная транскрибация;
- синхронизация между устройствами;
- мобильные версии;
- автоматическое резюмирование лекций;
- автоматическая коррекция медицинских фактов.
- пакетная очередь из нескольких аудиофайлов;
- одновременная транскрибация нескольких записей.

Эти возможности могут быть добавлены после стабилизации первой версии.

## 4. Пользовательский сценарий

1. Пользователь запускает VoxNote.
2. При первом запуске приложение предлагает выбрать модель, объясняет различия и показывает размер загрузки.
3. Пользователь скачивает одну модель. По умолчанию рекомендуется профиль «Сбалансированная».
4. Пользователь выбирает светлую, тёмную или системную тему.
5. Пользователь выбирает аудиофайл или перетаскивает его в окно.
6. Приложение проверяет формат и доступность файла.
7. Пользователь при необходимости меняет модель и выбирает словарь: «Без словаря», «Медицинская лекция» или пользовательский набор.
8. Если выбранная модель ещё не загружена, VoxNote предлагает скачать её до начала обработки.
9. Пользователь запускает транскрибацию.
10. VoxNote выбирает GPU либо CPU и показывает ход обработки.
11. После завершения приложение показывает единый текст без таймкодов и обозначений сегментов.
12. Пользователь копирует текст или сохраняет его рядом с исходным файлом либо в выбранную папку.

## 5. Интерфейс

### 5.1. Визуальное направление

Интерфейс должен сочетать минимализм Apple с плотностью и практичностью современных harness-приложений: Codex, DeepSeek и Visual Studio Code.

Основные принципы:

- спокойная нейтральная палитра;
- мягкие скругления и аккуратные тени;
- минимум визуального шума;
- короткие ненавязчивые анимации;
- ясная иерархия текста;
- одинаковая структура в светлой и тёмной темах;
- отсутствие блокировки интерфейса во время транскрибации.

### 5.2. Экраны

#### Первый запуск

- краткое описание локальной обработки;
- карточки моделей «Быстрая», «Сбалансированная» и «Максимальная точность»;
- краткое сравнение качества, скорости, размера и примерных требований;
- визуальная отметка рекомендуемой модели;
- информация о размере выбранной модели и свободном месте на диске;
- кнопка загрузки;
- полоса прогресса загрузки;
- обработка отмены, продолжения, повторной попытки и повреждённой загрузки.

#### Домашний экран

- спокойный стартовый экран без открытой заметки и выбранного файла;
- основное действие «Расшифровать аудио»;
- локальная сводка по количеству и общей длительности записей;
- список последних записей;
- быстрый переход к остановленной транскрибации;
- логотип приложения возвращает на домашний экран;
- открытую заметку можно закрыть без удаления, вернувшись на домашний экран.

#### Новая транскрибация

- зона выбора и перетаскивания файла;
- название, размер и продолжительность выбранного аудио;
- выбор модели с кратким описанием;
- выбор словаря;
- отображение выбранного устройства: Auto, NVIDIA GPU или CPU;
- кнопка «Транскрибировать».

#### Обработка

- название файла;
- реальная упрощённая форма звуковой волны с подсветкой уже обработанной части;
- название текущего этапа: подготовка, загрузка модели, распознавание или завершение;
- крупный процент готовности и отдельное значение «Осталось»;
- обработанная длительность относительно общей длительности аудио;
- прошедшее время и сглаженная оценка оставшегося времени;
- фактически используемые модель и устройство;
- кнопка отмены.

#### Результат

- документный редактор с заголовками, базовым форматированием, списками, цитатами, ссылками и отменой действий;
- переносимое хранение отредактированного текста в Markdown без облачной синхронизации;
- неизменяемая вкладка исходного результата модели и локальная история версий;
- кнопка «Копировать»;
- кнопка «Сохранить TXT»;
- кнопка «Новый файл»;
- сообщение об устройстве и словаре, использованных при распознавании.

#### Настройки

- светлая, тёмная или системная тема; по умолчанию используется тема Windows;
- автоматический выбор устройства, GPU или CPU;
- расположение модели;
- список доступных моделей, их размеры и состояние загрузки;
- скачивание, переключение и удаление моделей;
- предупреждение перед удалением модели, выбранной по умолчанию;
- управление пользовательскими словарями;
- очистка кеша.

### 5.3. Представление результата

Под «сплошным текстом» понимается единая расшифровка без таймкодов, номеров сегментов и подписей говорящих. Пунктуация и регистр сохраняются в том виде, в котором их восстановила модель. Допускаются абзацы в местах длинных пауз, чтобы многочасовая лекция не превращалась в один трудночитаемый блок.

В MVP приложение не исправляет стиль, факты и терминологию после распознавания. Сохранённый `.txt` должен совпадать с показанным результатом.

### 5.4. Язык анимаций

Анимация в VoxNote должна подтверждать действие, объяснять переход между состояниями и помогать считывать прогресс. Она не используется как самостоятельное украшение и не должна отвлекать от текста.

Базовые правила:

- реакция на нажатие или наведение начинается визуально без заметной задержки;
- микропереходы занимают примерно 83–167 мс;
- появление карточек, панелей и диалогов — около 167–250 мс;
- завершение операции может использовать акцентную анимацию до 400 мс;
- входящие элементы быстро появляются и мягко замедляются к конечной позиции;
- исчезающие элементы одновременно слегка смещаются и затухают;
- постоянные фоновые анимации медленные, малоконтрастные и прекращаются, когда процесс остановлен;
- не используются пружинящие перелёты, крупный параллакс, конфетти и многократные пульсации;
- цвет и движение никогда не являются единственным способом сообщить состояние.

Основные motion-токены:

| Токен | Длительность | Применение |
| --- | ---: | --- |
| `motion-faster` | 83 мс | нажатие, смена opacity, фокус |
| `motion-fast` | 167 мс | hover, переключатель, компактный tooltip |
| `motion-normal` | 250 мс | появление карточки, диалог, переход состояния |
| `motion-success` | 350–400 мс | завершение загрузки или транскрибации |

QML-анимации должны изменять преимущественно `opacity`, `scale`, `x`, `y` и простые цветовые свойства. Следует избегать тяжёлого blur, изменения геометрии больших теней и выполнения JavaScript на каждом кадре.

### 5.5. Анимации по состояниям

#### Пустой экран

- зона перетаскивания имеет едва заметный статичный контур;
- при наведении файла контур и фон плавно получают акцентный цвет;
- иконка файла смещается вверх на несколько пикселей;
- после отпускания файла карточка появляется через короткий fade-and-rise.

#### Загрузка модели

- используется определённый прогресс, основанный на реально полученных байтах;
- полоса движется только при поступлении данных;
- рядом показываются загруженный объём, общий объём и скорость;
- при временной остановке сети движение прекращается и появляется статус «Соединение прервано»;
- успешная проверка файла завершается короткой анимацией галочки.

#### Подготовка аудио

- пока длительность и форма волны ещё неизвестны, показывается компактный неопределённый индикатор;
- после чтения метаданных индикатор превращается в линию реальной звуковой волны без резкой смены макета;
- неопределённая анимация не должна изображать ложный процент.

#### Транскрибация

- звуковая волна остаётся неподвижной, а акцентная маска плавно открывает обработанную часть слева направо;
- процент меняется монотонно и визуально интерполируется между подтверждёнными значениями;
- небольшие индикаторы активности могут мягко двигаться только возле текущей позиции;
- текст статуса меняется через короткий cross-fade;
- анимация не должна создавать впечатление работы, если backend перестал сообщать прогресс.

#### Завершение

- обработанная маска доходит до конца;
- значение меняется на `100%` только после успешной финализации результата;
- появляется спокойная галочка и подпись «Транскрибация завершена»;
- кнопки результата проявляются одним последовательным переходом без каскада эффектов.

#### Ошибка

- цвет статуса меняется на предупреждающий;
- вместо агрессивной тряски используется короткое появление иконки и понятного текста;
- сохраняются уже введённые настройки и выбранный файл, если повторный запуск безопасен;
- кнопка исправляющего действия получает фокус.

### 5.6. Компоновка экрана обработки

Пример информационной иерархии:

```text
Лекция по кардиологии.m4a                     NVIDIA GPU
Сбалансированная · Медицинская лекция

Распознаём русскую речь
██████████████████░░░░░░░░░░░░░░░░░░░░

64% готово                         Осталось 36%
42:18 обработано из 1:05:54        Примерно 24 мин

                         [Отменить]
```

Числа имеют более высокий визуальный приоритет, чем декоративная волна. Основной статус всегда выражен текстом. На узком окне вторичные значения переносятся на следующую строку, не перекрывая кнопки.

### 5.7. Расчёт прогресса

VoxNote различает прогресс загрузки модели и прогресс транскрибации.

#### Загрузка модели

```text
download_percent = downloaded_bytes / total_bytes * 100
```

Если сервер не сообщает общий размер, вместо процента показывается неопределённый индикатор и количество уже загруженных данных. Запрещено подставлять предполагаемый процент.

#### Транскрибация

Основой является последняя подтверждённая временная позиция обработанного сегмента:

```text
audio_percent = processed_audio_seconds / total_audio_seconds * 100
remaining_percent = 100 - audio_percent
```

Правила:

- значение ограничивается диапазоном от 0 до 100;
- отображаемый процент никогда не уменьшается;
- скачок через участок тишины допустим, если движок действительно его обработал или пропустил через VAD;
- UI получает обновления не чаще 5–10 раз в секунду;
- мелкие скачки визуально сглаживаются, но подпись всегда основана на подтверждённых данных;
- окончание аудиопотока переводит экран в состояние «Формируем результат»;
- `100%` показывается только после сборки итогового текста;
- если длительность определить невозможно, показываются обработанное время и неопределённый прогресс без выдуманного процента.

### 5.8. Оценка оставшегося времени

Оценка появляется только после накопления достаточного количества данных: не ранее 30 секунд работы и не ранее обработки примерно 3% аудио.

Базовая оценка:

```text
processing_rate = processed_audio_seconds / elapsed_seconds
remaining_seconds = remaining_audio_seconds / processing_rate
```

Для интерфейса используется сглаженная скорость нескольких последних измерений. Это предотвращает скачки ETA при паузах, тишине и первом прогреве модели.

Правила отображения:

- до появления устойчивой оценки: «Рассчитываем оставшееся время…»;
- менее минуты: «Меньше минуты»;
- до десяти минут: округление примерно до минуты;
- длинные оценки: разумное округление без ложной точности;
- после сна компьютера, смены устройства, повторной инициализации или резкого изменения скорости оценка пересчитывается;
- при зависании backend вместо устаревшего ETA появляется «Нет прогресса, проверяем состояние…».

### 5.9. Реальная звуковая волна

Во время подготовки VoxNote строит низкодетализированный набор амплитудных пиков для всей записи. Он используется только для визуальной навигации и не влияет на распознавание.

- количество точек зависит от ширины окна, а не от длительности записи;
- исходное аудио не копируется и не сохраняется ради волны;
- обработанная часть окрашивается акцентным цветом;
- оставшаяся часть использует нейтральный цвет;
- при ошибке анализа применяется простой статичный индикатор, а транскрибация остаётся доступной;
- перестроение волны при изменении размера окна не должно повторно декодировать весь файл.

### 5.10. Доступность и снижение движения

- приложение учитывает системное предпочтение уменьшения анимаций, если оно доступно;
- в настройках есть отдельный переключатель «Уменьшить анимации»;
- в этом режиме отключаются циклические эффекты, а переходы сокращаются до короткого fade или происходят мгновенно;
- все действия доступны с клавиатуры;
- порядок фокуса соответствует визуальному порядку;
- статусы и прогресс имеют текстовые подписи для screen reader;
- контраст текста и элементов управления проверяется в обеих темах;
- мигающие и быстро пульсирующие эффекты не используются.

### 5.11. Производительность интерфейса

- декодирование, построение волны, загрузка модели и транскрибация не выполняются в UI-потоке;
- backend не отправляет интерфейсу событие на каждый аудиосэмпл;
- сложные QML-выражения не вычисляются на каждом кадре;
- тяжёлые blur и динамические тени не анимируются;
- при высокой загрузке GPU декоративные эффекты могут автоматически упрощаться;
- плавность интерфейса проверяется одновременно с работой `large-v3`, а не только в состоянии покоя;
- изменение темы во время обработки не перезапускает задачу.

### 5.12. Визуальные токены

Интерфейс строится на семантических токенах, а не на случайных значениях в отдельных QML-файлах.

#### Геометрия

- базовая сетка — 4 px, основные интервалы кратны 8 px;
- внутренний отступ карточек — 16–20 px;
- скругление компактных элементов — около 8–10 px;
- скругление основных карточек и диалогов — около 14–16 px;
- основной контент ограничен комфортной шириной, а свободное пространство используется осознанно;
- тонкая рамка предпочтительнее тяжёлой тени;
- тень используется только для плавающих поверхностей и диалогов.

#### Цвет

- используются семантические роли: `background`, `surface`, `surface-raised`, `text-primary`, `text-secondary`, `border`, `accent`, `success`, `warning`, `error`;
- чистый чёрный и чистый белый не используются на больших поверхностях;
- один основной акцентный цвет связывает выбор файла, прогресс и основное действие;
- медицинский словарь не получает отдельный тревожный цвет: это профиль терминов, а не предупреждение;
- градиент допустим только как очень мягкий акцент состояния и не заменяет контрастную рамку или подпись.

#### Типографика

- основной шрифт — системный `Segoe UI Variable` с безопасным fallback;
- заголовки короткие и не используют чрезмерно жирное начертание;
- вторичный текст не становится настолько бледным, что теряет читаемость;
- проценты, длительности и ETA используют табличные цифры, чтобы ширина строки не дёргалась при обновлении;
- текст результата отображается шрифтом, оптимизированным для длительного чтения, с комфортной высотой строки.

#### Компоненты

- основная кнопка на экране только одна;
- вторичные действия визуально спокойнее и не конкурируют с запуском транскрибации;
- прогресс-линия имеет постоянную толщину и не меняет высоту при обновлении;
- выбранная модель и словарь обозначаются рамкой, фоном и иконкой, а не только цветом;
- состояния hover, pressed, focus, disabled и error проектируются для каждого интерактивного компонента;
- длинные имена файлов сокращаются посередине или в конце, а полное имя доступно в tooltip.

## 6. Терминологические словари

### 6.1. Цель

Словарь сообщает движку, какие редкие слова и устойчивые выражения могут встретиться в записи. Например, медицинская лекция может содержать названия препаратов, анатомические термины и фамилии исследователей, которые обычная модель распознаёт неверно.

Словарь является подсказкой для модели, а не механизмом безусловной замены текста. Наличие термина повышает вероятность правильного распознавания, но не гарантирует результат.

### 6.2. Варианты выбора

В MVP доступны:

- **Без словаря** — стандартное распознавание;
- **Медицинская лекция** — встроенный русскоязычный набор терминов;
- **Пользовательский словарь** — импортированный пользователем список слов и выражений.

Архитектура должна позволять позднее добавить словари для юриспруденции, программирования, истории, химии и других областей без изменения движка приложения.

### 6.3. Медицинский словарь

Первая встроенная версия может включать категории:

- анатомия;
- физиология;
- фармакология;
- заболевания и синдромы;
- диагностические процедуры;
- лабораторные показатели;
- медицинские аббревиатуры;
- фамилии учёных и названия методик.

Примеры терминов:

- ацетилхолин;
- ангиотензин;
- глюкокортикостероиды;
- электрокардиография;
- эхокардиография;
- гемоглобин;
- гипоксия;
- ишемия;
- нейромедиатор;
- парасимпатическая нервная система;
- ренин-ангиотензин-альдостероновая система;
- систолическое давление;
- диастолическое давление.

Это только демонстрационный набор. Перед публичным релизом словарь должен пройти ручную проверку орфографии, источников и лицензий.

### 6.4. Пользовательский словарь

В первой версии поддерживается импорт `.txt`, где каждый термин или выражение находится на отдельной строке:

```text
ацетилхолинэстераза
атриовентрикулярный узел
круг кровообращения
метопролол
```

Правила импорта:

- кодировка UTF-8;
- пустые строки игнорируются;
- пробелы в начале и конце удаляются;
- одинаковые записи объединяются без учёта регистра;
- чрезмерно длинные строки отклоняются;
- перед применением показывается количество найденных терминов;
- исходный пользовательский файл не изменяется.

Позднее можно добавить редактор словарей и структурированный формат JSON.

### 6.5. Внутренний формат

Встроенные словари рекомендуется хранить в JSON:

```json
{
  "id": "medical-ru",
  "name": "Медицинская лекция",
  "description": "Русские медицинские термины для лекций и докладов",
  "language": "ru",
  "version": 1,
  "terms": [
    "ацетилхолин",
    "электрокардиография",
    "ренин-ангиотензин-альдостероновая система"
  ]
}
```

Планируемое расположение:

```text
resources/
  dictionaries/
    medical_ru.json
```

### 6.6. Передача терминов движку

Перед транскрибацией приложение:

1. загружает выбранный словарь;
2. проверяет и нормализует записи;
3. ограничивает объём подсказки до безопасного размера;
4. формирует русскоязычную контекстную подсказку с приоритетными терминами;
5. передаёт полный упорядоченный список через `hotwords`; фактическое число токенов ограничивает сам Whisper;
6. сохраняет в метаданных сеанса идентификатор и версию словаря.

Если движок поддерживает отдельный механизм hotwords, адаптер может использовать его. Детали конкретной библиотеки не должны проникать в UI: интерфейс работает с абстракцией `DictionaryProfile`.

### 6.7. Ограничения безопасности

- VoxNote не должен автоматически заменять похожие слова только потому, что они есть в словаре.
- Для медицинских записей особенно важно не вносить незаметные смысловые изменения.
- Словарь не является медицинской базой знаний и не проверяет достоверность лекции.
- В интерфейсе следует указать, что итоговую расшифровку необходимо проверить перед профессиональным использованием.
- Пользовательские словари и аудио никогда не отправляются во внешние сервисы.

## 7. Техническая архитектура

### 7.1. Рекомендуемый стек

- Python 3.11;
- PySide6;
- Qt Quick/QML;
- faster-whisper;
- CTranslate2;
- PyAV/FFmpeg для декодирования;
- PyInstaller или `pyside6-deploy`;
- Inno Setup для установщика;
- pytest для автоматических тестов;
- GitHub Actions для сборок и релизов.

### 7.2. Компоненты

```text
QML UI
  -> Application Controller
    -> Audio Validator
    -> Audio Metadata & Waveform Service
    -> Model Manager
    -> Dictionary Manager
    -> Device Detector
    -> Transcription Service
      -> faster-whisper adapter
    -> Progress & ETA Estimator
    -> Local Session Store
    -> TXT Exporter
```

Интерфейс не должен напрямую вызывать faster-whisper. Отдельный адаптер позволит заменить или обновить движок без переработки экранов.

### 7.3. Фоновая обработка

Транскрибация выполняется вне главного UI-потока. Сервис передаёт интерфейсу события:

- загрузка модели;
- начало обработки;
- текущая позиция в аудио;
- процент выполнения;
- приблизительное оставшееся время;
- признак активности backend и время последнего подтверждённого прогресса;
- полученный фрагмент текста;
- завершение;
- отмена;
- ошибка.

Отмена должна происходить между обрабатываемыми сегментами и не повреждать исходный файл.

### 7.4. Выбор устройства

Режим `Auto`:

1. проверить наличие совместимой NVIDIA GPU и необходимых библиотек;
2. выполнить короткую безопасную инициализацию движка;
3. использовать GPU при успешной проверке;
4. при ошибке освободить ресурсы и перейти на CPU;
5. сообщить пользователю о фактически выбранном устройстве.

Для CPU используется экономичный режим вычислений. Для GPU режим выбирается с учётом доступной видеопамяти. Ошибка нехватки памяти должна приводить к понятному предложению перейти на CPU, а не к аварийному завершению приложения.

### 7.5. Дистрибуция приложения и ML-runtime

- Tauri/React-приложение распространяется отдельно от Python ML-runtime и CUDA-библиотек.
- При первом запуске пользователь явно выбирает CPU/core runtime или CPU/core runtime с ускорением NVIDIA; скрытая автоматическая загрузка запрещена.
- Runtime хранится версионно в `%LOCALAPPDATA%\VoxNote\runtime`; обновление оболочки не удаляет и не распаковывает его повторно.
- Каждый runtime-пакет имеет фиксированные URL, размер и SHA-256. Загрузка идёт во временный файл, а установка активируется атомарно только после проверки и безопасной распаковки.
- CPU-сборка не предлагает CUDA только из-за наличия видеокарты: режим NVIDIA доступен packaged-runtime лишь при установленном accelerator pack.
- Проверка новой версии приложения может выполняться автоматически. Скачивание, установка и перезапуск выполняются только после явного действия пользователя.
- Поддерживаются отдельные CPU Portable и Full NVIDIA Portable без обращения к системному Python.

## 8. Выбор моделей и управление ими

### 8.1. Зачем нужен выбор

У моделей Whisper разный баланс скорости, качества и потребления памяти. Нельзя обещать одинаковую скорость на всех компьютерах: она зависит от процессора, видеокарты, объёма памяти, качества записи и параметров распознавания. Поэтому VoxNote показывает не технический список всех checkpoint-файлов, а три понятных пользовательских профиля.

Все модели MVP являются многоязычными. При транскрибации VoxNote явно задаёт русский язык и задачу распознавания, а не перевода.

### 8.2. Модели MVP

| Режим в интерфейсе | Техническая модель | Размер загрузки | Для кого | Основной компромисс |
| --- | --- | ---: | --- | --- |
| **Быстрая** | `small` | около 0,5 ГБ | слабые компьютеры, CPU и быстрые черновики | быстрее и компактнее, но чаще ошибается в редких терминах и плохих записях |
| **Сбалансированная** | `large-v3-turbo` (`turbo`) | около 1,6 ГБ | большинство пользователей и длинные лекции | близкое к крупной модели качество при существенно более высокой скорости; рекомендуется по умолчанию |
| **Максимальная точность** | `large-v3` | около 3,1 ГБ | сложная речь, шумные записи и приоритет качества | медленнее, требует больше RAM/VRAM и места на диске |

Размеры относятся к файлам моделей CTranslate2 и могут немного измениться после обновления репозитория модели. В интерфейсе необходимо показывать фактический размер из версионируемого каталога, поставляемого вместе с VoxNote, до начала загрузки.

Техническое имя модели показывается в раскрываемом блоке «Подробнее», а не в основном заголовке карточки. Пользователь выбирает понятный режим, но всегда может увидеть точный checkpoint и источник загрузки.

### 8.3. Предварительные требования

Эти значения являются начальными продуктовыми ориентирами, а не гарантией совместимости. Перед релизом они должны быть подтверждены тестами на реальных компьютерах.

| Модель | Ориентир для CPU | Ориентир для NVIDIA GPU | Рекомендуемый сценарий |
| --- | --- | --- | --- |
| `small` | от 4 ГБ свободной RAM | от 2 ГБ свободной VRAM | слабый ПК или быстрый черновик |
| `turbo` | от 8 ГБ свободной RAM | от 4 ГБ свободной VRAM | стандартный режим VoxNote |
| `large-v3` | от 12 ГБ свободной RAM | от 6 ГБ свободной VRAM | максимальное качество |

VoxNote не должен запрещать запуск только по формальной оценке памяти. Приложение предупреждает о возможной нехватке ресурсов, пробует безопасную инициализацию и предлагает меньшую модель либо CPU при ошибке.

### 8.4. Что означают характеристики

- **Качество** — вероятность получить правильные слова, пунктуацию и окончания. Даже максимальная модель может ошибаться.
- **Скорость** — отношение времени обработки к длительности аудио. Оно измеряется на конкретном устройстве, поэтому в каталоге не показывается универсальное обещание вида «час за пять минут».
- **Размер загрузки** — объём данных, скачиваемых один раз. После загрузки модель работает без интернета.
- **RAM** — оперативная память компьютера, используемая при обработке на CPU и частично на GPU.
- **VRAM** — память NVIDIA GPU. Её нехватка может вызвать переход на CPU или предложение выбрать меньшую модель.

### 8.5. Почему не показываются остальные модели

- `tiny` и `base` не входят в MVP из-за заметной потери качества на длинных русскоязычных лекциях.
- `medium` не показывается, чтобы не перегружать выбор: профиль `turbo` занимает близкую продуктовую нишу и должен быть сначала сравнен с ним на русском тестовом наборе.
- англоязычные модели с суффиксом `.en` не подходят, поскольку VoxNote ориентирован на русский язык.
- Distil-Whisper не включается в MVP: основные опубликованные distilled-модели ориентированы прежде всего на английскую речь.
- старые `large-v1` и `large-v2` не предлагаются новым пользователям; они могут быть добавлены позднее только ради совместимости или подтверждённого преимущества на русском наборе.

Перед заморозкой состава моделей необходимо провести собственный сравнительный тест `small`, `medium`, `turbo` и `large-v3` на русских лекциях. Если `medium` окажется точнее `turbo` при приемлемой скорости, решение о трёх профилях пересматривается до публичного релиза.

### 8.6. Поведение выбора

- при первом запуске по умолчанию выделена «Сбалансированная» модель, но загрузка начинается только после подтверждения пользователя;
- возле каждой модели показываются размер, назначение и статус: «Не загружена», «Загрузка», «Готова» или «Ошибка»;
- выбор незагруженной модели не запускает транскрибацию автоматически, а открывает подтверждение загрузки;
- одновременно активна только одна модель;
- пользователь может хранить несколько моделей и переключаться без повторной загрузки;
- удаление модели не удаляет расшифровки, словари и настройки;
- последнюю установленную модель можно удалить, но приложение предупреждает, что транскрибация станет недоступна;
- модель, словарь и устройство фиксируются в начале задания и не меняются посреди обработки.

### 8.7. Загрузка и целостность

- модели не входят в установщик;
- источники, зафиксированные ревизии, размеры и контрольные суммы задаются версионируемым каталогом, поставляемым вместе с VoxNote;
- перед загрузкой показываются модель, источник, размер и необходимое свободное место;
- загрузка поддерживает прогресс, отмену, повторную попытку и продолжение после обрыва, если это допускает источник;
- временный файл не считается установленной моделью;
- после загрузки проверяются ожидаемые файлы и контрольные суммы;
- модель становится доступной только после атомарного переноса из временной папки;
- модели хранятся в `%LOCALAPPDATA%\VoxNote\models`;
- после загрузки интернет для транскрибации не требуется;
- обновление каталога не должно молча заменять уже установленную и работающую модель.

Каталог обновляется вместе с приложением. Для MVP не требуется отдельный удалённый сервис каталога: это уменьшает поверхность атаки и сохраняет предсказуемость сборки.

### 8.8. Автоматический выбор вычислений

Для каждой модели движок выбирает режим отдельно:

1. в режиме `Auto` проверяется NVIDIA GPU;
2. выполняется безопасная загрузка модели с подходящим типом вычислений;
3. при нехватке VRAM сначала предлагается экономичный GPU-режим, если он поддерживается;
4. если GPU недоступна, приложение переходит на CPU и уведомляет пользователя;
5. при нехватке RAM предлагается меньшая модель, а задание не запускается повторно без подтверждения.

Фактически выбранные модель, устройство и тип вычислений отображаются на экране обработки и записываются только в технические метаданные локального сеанса.

### 8.9. Проверка качества моделей

Окончательный набор моделей нельзя утверждать только по сторонним англоязычным benchmark-таблицам. Перед релизом VoxNote формирует собственный воспроизводимый отчёт на русском материале.

Минимальный тестовый набор должен включать:

- чистую запись лекции с одним говорящим;
- запись с фоновым шумом;
- запись с тихой или удалённой речью;
- медицинскую лекцию без словаря и с медицинским словарём;
- короткую запись и запись продолжительностью не менее часа.

Для каждой модели фиксируются:

- доля ошибок слов или символов на вручную проверенном фрагменте;
- время обработки и коэффициент относительно длительности аудио;
- пиковое потребление RAM и VRAM;
- устройство и тип вычислений;
- версия VoxNote, faster-whisper, CTranslate2 и модели;
- влияние словаря на редкие термины;
- случаи повторов, пропусков и ложного текста на тишине.

Отчёт сохраняется в `docs/model-benchmark.md`. Пользовательские формулировки «Быстрая», «Сбалансированная» и «Максимальная точность» должны соответствовать результатам этого теста, а не только ожидаемому размеру модели.

## 12. Критерии готовности MVP

MVP считается готовым, когда:

- приложение устанавливается на Windows 10/11;
- модель успешно загружается при первом запуске;
- пользователь понимает различия между тремя моделями до загрузки;
- можно установить, переключить и удалить каждую модель;
- фактические требования моделей подтверждены тестовым отчётом;
- после загрузки приложение работает без интернета;
- поддерживаемый аудиофайл можно выбрать или перетащить;
- русская речь преобразуется в сплошной текст;
- интерфейс остаётся отзывчивым;
- показывается достоверный процент обработанного и оставшегося аудио;
- до получения достаточных данных ETA честно показывает состояние расчёта;
- оценка оставшегося времени сглаживается и пересчитывается после изменения скорости;
- `100%` появляется только после готовности итогового текста;
- форма волны отражает реальный аудиофайл либо явно заменяется нейтральным fallback-индикатором;
- анимации соответствуют состоянию backend и прекращаются при остановке прогресса;
- режим уменьшения анимаций отключает циклическое движение;
- GPU используется при совместимости, иначе работает CPU;
- при нехватке памяти предлагается понятное безопасное действие вместо аварийного завершения;
- можно выбрать медицинский или пользовательский словарь;
- словарь влияет на подсказку модели, но не выполняет опасных безусловных замен;
- результат копируется и сохраняется в UTF-8 `.txt`;
- светлая и тёмная темы работают корректно;
- системная тема корректно следует настройке Windows;
- приложение не отправляет телеметрию и не выполняет скрытых сетевых запросов во время транскрибации;
- исходный код и инструкция сборки опубликованы на GitHub.

## 15. Сценарии и состояния приложения

### 15.1. Модель состояний

Главный экран управляется явной машиной состояний. В каждый момент активен один основной статус:

```text
STARTING
  -> ONBOARDING
  -> MODEL_REQUIRED
  -> IDLE
  -> FILE_SELECTED
  -> PREPARING_AUDIO
  -> LOADING_MODEL
  -> TRANSCRIBING
  -> FINALIZING
  -> COMPLETED
  -> CANCELLED
  -> ERROR
```

Загрузка модели имеет отдельные подстатусы:

```text
NOT_INSTALLED -> DOWNLOADING -> VERIFYING -> INSTALLED
                         \-> PAUSED / FAILED / CANCELLED
```

Переходы выполняет контроллер приложения. QML только отображает переданное состояние и не принимает самостоятельных решений о завершении задачи.

### 15.9. Общие правила ошибок

- ошибка описывает, что произошло, что сохранилось и какое действие доступно;
- технические детали доступны через раскрываемый блок и кнопку копирования;
- сообщение не обвиняет пользователя и не предлагает абстрактное «Попробуйте ещё раз» без контекста;
- ошибка модели не удаляет аудио, словарь и уже готовый текст;
- повторный запуск не выполняется автоматически, если он может занять много времени или изменить устройство;
- секреты, пути других пользователей и содержимое расшифровки не включаются в диагностические логи;
- анимация ошибки заканчивается, а не повторяется бесконечно.

### 15.10. Приоритет реализации

Сценарии с пометкой **MVP** входят в критерии первой публичной версии. Пометка **После MVP** означает, что интерфейс и архитектура не должны блокировать будущую функцию, но её отсутствие не задерживает первый релиз.

Перед началом реализации для каждого состояния создаётся отдельный макет и набор переходов. Это позволяет проверить полный пользовательский путь до подключения тяжёлого движка распознавания.
